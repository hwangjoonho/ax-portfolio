Overview
앱과 웹을 넘나드는 시나리오

실제 운영에서 회원가입은 앱에서 가입 → 관리자 웹에서 승인 → 앱에서 후속 진행으로 앱과 웹을 오갑니다. 이 흐름을 특정 단말 1대에서 자동 검증합니다. 모바일은 Patrol, 관리자 웹은 Playwright가 맡고, 가운데 경량 브리지 서버가 양쪽 신호를 중계해 '핑퐁'처럼 단계를 주고받습니다.

왜 브리지 서버인가. 디바이스 측 Patrol과 웹 측 Playwright는 서로 직접 통신할 수 없습니다. 그래서 가운데 localhost:8090 경량 HTTP 서버를 두고, 한쪽이 단계를 끝내면 신호를 올리고 다른 쪽이 그 신호를 consume한 뒤 자기 단계를 진행합니다. 신호가 양방향으로 오가며 하나의 시나리오가 완성됩니다.
Scenario
회원가입 핑퐁 흐름
  1. 01 앱 — 회원가입 — Patrol이 모바일 앱에서 신규 회원가입 폼을 작성/제출
  2. 02 앱 → 브리지 — 가입 완료 신호를 브리지 서버로 전송 signup_complete
  3. 03 웹 — 승인 처리 — Playwright가 관리자 웹에서 해당 회원을 조회하고 승인
  4. 04 웹 → 브리지 — 승인 완료 신호를 브리지 서버로 전송 admin_verified
  5. 05 앱 — 후속 진행 — 승인 신호를 consume하고 로그인 등 후속 시나리오를 이어서 검증
Features
핵심 포인트
01
양방향 신호 교환
signup_complete(앱→웹)와 admin_verified(웹→앱)를 양쪽이 번갈아 consume하며 시나리오를 함께 완성합니다.
02
경량 브리지 서버
Node.js Express로 만든 작은 HTTP 서버(localhost:8090). Patrol이 권장하는 localhost HTTP 패턴에 맞춰 신호를 중계합니다.
03
Workspace 단위 격리
빌드 워크스페이스 범위의 신호 파일 + flock 락으로, 동시/연속 빌드 간 신호가 섞이지 않도록 격리합니다.
04
Trace Viewer 시각화
Playwright trace.zip을 아티팩트로 저장해, 사후에 웹 단계를 한 스텝씩 재생하며 진행 화면을 확인할 수 있습니다.
05
단일 단말 멱등 실행
전용 단말에서 관련 패키지를 명시적으로 uninstall 후 fresh install. 매 빌드가 같은 초기 상태에서 시작합니다.
06
실제 운영 플로우 검증
단위 화면이 아니라 앱↔웹을 넘나드는 가입 승인 같은 실제 cross-app 업무 플로우를 자동으로 검증합니다.
